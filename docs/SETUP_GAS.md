# 匿名集計（Google Apps Script）のセットアップ手順

診断結果を匿名で Google スプレッドシートに保存し、「みんなのランキング」に表示するための手順です。
費用はかかりません。作業は Google にログインしたブラウザ（PC推奨）で行います。所要時間は15分ほどです。

> この手順が終わるまでは、サイトの `config.js` の `gasUrl` が空のままなので、
> 送信と「みんなのランキング」は自動的に無効になっています（診断はそのまま使えます）。

---

## 1. Google スプレッドシートを新規作成する

1. ブラウザで https://sheets.new を開く（Google ドライブで「新規 → Google スプレッドシート」でも同じ）。
2. 左上の「無題のスプレッドシート」をクリックし、名前を付ける（例：`ビートルズTOP10 集計`）。
3. **共有設定は変更しない**（右上の「共有」ボタンは押さない）。非公開のままで動きます。
   サイトの利用者が見られるのは集計結果（曲ごとの割合）だけで、スプレッドシート自体は見られません。

## 2. Apps Script を開き、コードを貼り付ける

1. スプレッドシートのメニューで **「拡張機能」→「Apps Script」** を選ぶ。新しいタブでエディタが開きます。
2. 左上の「無題のプロジェクト」をクリックし、名前を付ける（例：`beatles-top10-stats`）。
3. 左の「ファイル」にある **`コード.gs`** を開き、中に書かれている `function myFunction() { ... }` を**すべて削除**する。
4. このリポジトリの **`gas/Code.gs` の中身をすべてコピーして貼り付ける**。
   - 1行目が `/** @OnlyCurrentDoc */` になっていることを確認してください。これにより、スクリプトが触れられるのは**このスプレッドシートだけ**になります。
5. 上部のフロッピーディスクのアイコン（**プロジェクトを保存**）を押す（`⌘ + S` / `Ctrl + S` でも可）。

### 初回の準備（setup を1回だけ実行）

1. エディタ上部の「実行」ボタンの右にある関数の選択欄で **`setup`** を選ぶ。
2. **「実行」** を押す。
3. 「承認が必要です」と表示されたら、**「権限を確認」** を押し、自分の Google アカウントを選ぶ。
4. **「Google がこのアプリを確認していません」**（英語では “Google hasn’t verified this app”）という警告が出ます。

   > **これは自作のスクリプトでは正常な表示です。**
   > Google が審査していないアプリ（＝あなたが今貼り付けたコード）を、あなた自身のアカウントで動かそうとしているために出ます。
   > このスクリプトが使う権限は「このスプレッドシートの表示・編集」だけで（`@OnlyCurrentDoc` の効果）、
   > ほかのファイルやメール、外部への送信には触れません。

   進め方：
   1. 左下の **「詳細」**（Advanced）を押す。
   2. 表示された **「（プロジェクト名）（安全ではないページ）に移動」** を押す。
   3. 権限の一覧が出たら内容を確認し（チェック欄がある場合は「すべて選択」）、**「許可」**（または「続行」）を押す。
5. 下の「実行ログ」に `aggregate: 0 rows ...` と出れば成功です。
   スプレッドシートに戻ると、**`responses`** と **`summary`** の2つのシートができています。
   （最初からある「シート1」は削除してかまいません。）

## 3. ウェブアプリとしてデプロイする

1. エディタ右上の **「デプロイ」→「新しいデプロイ」** を押す。
2. 「種類の選択」の横の **歯車アイコン** を押し、**「ウェブアプリ」** を選ぶ。
3. 次のように設定する。
   | 項目 | 設定 |
   |---|---|
   | 説明 | 任意（例：`v1`） |
   | 次のユーザーとして実行 | **自分**（あなたのメールアドレス） |
   | アクセスできるユーザー | **全員** |

   - 「全員」にしないと、サイトの利用者が送信・取得できません。「全員」でも、利用者にできるのは
     `doPost`（検証を通った診断結果の追加）と `doGet`（集計結果の取得）だけで、スプレッドシートは見えません。
   - 「自分として実行」なので、あなたのメールアドレスなどが利用者に知られることはありません。
4. **「デプロイ」** を押す。ここで再び承認を求められた場合は、手順2と同じように進めます。
5. 表示された **「ウェブアプリ」の URL**（`https://script.google.com/macros/s/……/exec` で終わるもの）を **コピー** する。
   「完了」を押して閉じます。

### 動作確認

コピーしたURLをブラウザの新しいタブで開き、次のような文字（JSON）が表示されれば成功です。

```
{"v":1,"updatedAt":"…","modes":{"all":{"n":0,"top10":{},"top3":{},"picks1":{}}, …}}
```

## 4. 集計用のトリガーを設定する（1時間ごと）

集計はアクセスのたびではなく、1時間ごとにまとめて行います。

1. Apps Script エディタの左端にある **時計のアイコン（トリガー）** を押す。
2. 右下の **「トリガーを追加」** を押す。
3. 次のように設定する。
   | 項目 | 設定 |
   |---|---|
   | 実行する関数を選択 | **`aggregate`** |
   | 実行するデプロイを選択 | **Head** |
   | イベントのソースを選択 | **時間主導型** |
   | 時間ベースのトリガーのタイプを選択 | **時間ベースのタイマー** |
   | 時間の間隔を選択 | **1時間おき** |
   | エラー通知設定 | 「毎日通知を受け取る」（おすすめ） |
4. **「保存」** を押す。承認を求められたら手順2と同じように進めます。

## 5. 発行されたURLを `config.js` に書く

リポジトリの `config.js` を開き、`gasUrl` に手順3でコピーしたURLを貼り付けます。

```js
window.BEATLES_CONFIG = {
  gasUrl: 'https://script.google.com/macros/s/XXXXXXXXXXXX/exec'
};
```

保存してサイトに反映（GitHub に push）すると、次の機能が有効になります。

- 結果画面の「集計に参加する（匿名）」チェックボックスと、診断結果の送信
- トップ画面・結果画面の「みんなのランキングを見る」ボタン
- フッターの「診断結果は匿名で集計され、全体ランキングに使われます」の表示

ランキングは、回答が **30件以上** 集まるまでは「集計中」と表示されます（モードごとに判定）。

## 6. コードを更新したときの再デプロイ（URLを変えずに更新する）

`gas/Code.gs` を変更したら、エディタの `コード.gs` に貼り直して保存し、次の手順で更新します。

1. 右上の **「デプロイ」→「デプロイを管理」** を押す。
2. 一覧から今のデプロイ（ウェブアプリ）を選び、右上の **鉛筆アイコン（編集）** を押す。
3. **「バージョン」で「新バージョン」** を選ぶ。
4. **「デプロイ」** を押す。

これで **URLは変わらずに** 新しいコードが使われます。

> **注意**：「新しいデプロイ」を使うと、**別のURL**が発行されてしまいます。その場合は `config.js` の書き換えが必要です。
> 集計（`aggregate`）のトリガーは「Head」（保存済みの最新コード）を使うので、再デプロイしなくても反映されます。

## 7. 怪しいデータを除外する／全データをリセットする

### 怪しいデータを集計から除外する

1. スプレッドシートの **`responses`** シートを開く。
2. 除外したい行の **G列「除外フラグ」** に `1`（または `x` など、空でない値）を入力する。
   - G列を選んで「挿入 → チェックボックス」を使い、チェックを入れる方法でもかまいません。
   - `FALSE` と `0` は「除外しない」として扱われます。
3. 次の集計（最大1時間後）で反映されます。すぐに反映したいときは、Apps Script エディタで
   関数 **`aggregate`** を選んで **「実行」** を押します。

怪しいデータの目安：短時間に同じような内容がまとめて届いている、`picks1` が極端に多い行が続く、など。

### 全データをリセットする

1. **`responses`** シートで、**2行目から最後の行までを選択** する（行番号の「2」をクリックし、`Shift` を押しながら最後の行番号をクリック）。
2. 右クリック → **「行を削除」**。1行目（見出し）は消さないでください。
3. Apps Script エディタで関数 **`aggregate`** を選んで **「実行」** を押し、集計結果を空にします。

> シートごと削除してしまった場合も、関数 **`setup`** を実行すれば作り直せます。

## 補足

### 受け付ける条件（サーバー側の検証）

次のどれかを満たさない送信は、保存せずに破棄します（`gas/Code.gs` の `validatePayload`）。

- 本文が 5KB 以下の JSON で、項目が `v` / `sid` / `mode` / `picks1` / `top10` / `top3` の6つだけ
- `v` が `1`、`mode` が `simple` か `detailed`、`sid` が UUID の形式
- 曲IDがすべて有効なIDで、重複がない
- `top3` はちょうど3件ですべて `top10` に含まれる、`top10` は1〜10件、`picks1` は72件以下
  （①は24画面 × 最大3曲のため。両モード共通）
- 同じ `sid` がまだ保存されていない
- 1分あたりの受付件数が上限（初期値300件）以内。上限は `Code.gs` 先頭の `RATE_LIMIT_PER_MINUTE` で変えられます

保存するのは、受信日時・sid・mode・曲IDをカンマでつないだ文字列だけです。名前・IPアドレス・ユーザーエージェントなどは受け取りも保存もしません。
破棄した理由は、Apps Script エディタ左の「実行数」から各実行のログ（`rejected: …`）で確認できます。利用者への応答には含めません。

### 無料枠について

Apps Script は無料で使えますが、1日あたりの実行時間などに上限があります（トリガーの合計実行時間は1日90分など）。
このサイトの規模なら通常は問題ありません。上限に達した場合はその日の受付や集計が止まり、翌日に回復します。

### 届いたデータを確認したいとき

`responses` シートを見てください。送信は、結果画面で「共有・保存・もう一度診断・ランキング」のいずれかを押したとき、
ページを閉じたとき、または結果画面を開いて15秒たったときに、1回だけ行われます（チェックを外すと送信されません）。
